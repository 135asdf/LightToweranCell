# 制作塔和敌人完整流程

> 适用于 Godot 4.6 工程（资源驱动组件架构）。本文档说明新增**普通塔**和**普通敌人**的完整步骤，含全部文件模板。
> 团队协作遵守 `docx/CONTRIBUTING.md`（分支 + PR、提交信息规范、禁止提交 `.godot/`）。

---

## 0. 架构总览（先读 3 分钟）

四层职责，缺一不可：

| 层 | 内容 | 举例 |
|---|---|---|
| **Resource** | 静态数值，唯一事实来源 | `MonsterData`、`TowerData`、`WaveData`、`LevelData`、`TowerCatalog` |
| **Scene** | 节点装配（继承复用） | `enemy_base.tscn`、`tower_base.tscn` → 内容场景 |
| **Component** | 运行时行为 + 状态 | 敌人 7 组件、关卡 5 组件 |
| **Controller** | 装配 + 连线 + 稳定接口 | `MonsterBase`、`TowerBase`、`LevelController` |

铁律：

- 平衡数值**只写进 `.tres`**，脚本/场景不复制同义字段
- **运行时状态不得写入 Resource**（当前血量、当前目标、当前能量都是组件状态）
- 继承场景覆写子节点：必须用 `name="节点名"` + `parent="父路径"`，**不要**在 `name` 里写斜杠（`name="Visual/Sprite2D"` 不会生效，贴图会消失）
- 组件间用 signal 通信；Controller 可以调用组件方法

## 1. 文件目录约定

| 内容 | 位置 | 命名 |
|---|---|---|
| 敌人数据 | `data/enemies/` | `enemy_<怪物名>.tres` |
| 敌人场景 | `scenes/enemies/` | `enemy_<怪物名>.tscn`（继承 `enemy_base.tscn`） |
| 塔数据 | `data/towers/` | `<塔名>_stats.tres` |
| 塔场景 | `scenes/towers/` | `<塔名>.tscn`（继承 `tower_base.tscn`） |
| 塔脚本 | `scripts/towers/` | `<塔名>.gd` |
| 敌人贴图 | `Textures/enemies/<怪物名>/` | 如 `vibrio.png` |
| 塔贴图 | `Textures/towers/<塔名>/` | 如 `vibrio.png` |

根节点命名帕斯卡：`EnemyStreptococcus`、`LightTower`；**不要用 `1_Enemy` 这类编号命名**。

## 2. 制作普通敌人：完整流程

以新增「弧菌 Vibrio」为例。共 **2 个新文件 + 2 处修改**。

### 2.1 定义敌人定位

决定：普通/快速/肉盾/精英/Boss（`monster_type`）、血量、移速、撞水晶伤害、有无特殊能力。

### 2.2 创建数据资源 `data/enemies/enemy_vibrio.tres`

```text
[gd_resource type="Resource" script_class="MonsterData" format=3]

[ext_resource type="Script" path="res://base/enemy_base/monster_data.gd" id="1_data"]

[resource]
script = ExtResource("1_data")
monster_id = &"vibrio"
display_name = "弧菌"
monster_type = 0
max_health = 120
armor = 0.0
move_speed = 60.0
contact_damage = 10
reach_distance = 20.0
negative_status_resistance = 0.0
score_value = 10
energy_reward = 0
```

字段说明：

| 字段 | 含义 | 示例 |
|---|---|---|
| `monster_id` | 稳定标识（snake_case，代码用） | `vibrio` |
| `display_name` | 显示名（可本地化） | 弧菌 |
| `monster_type` | 0=普通 1=精英 2=Boss | 0 |
| `max_health` / `armor` | 生命 / 抗性 0~1（承伤 ×(1-armor)） | 120 / 0.0 |
| `move_speed` | 移速（px/s） | 60.0 |
| `contact_damage` / `reach_distance` | 撞水晶伤害 / 到达判定距离 | 10 / 20.0 |
| `negative_status_resistance` | 减速等负面抗性 0~1 | 0.0 |
| `score_value` / `energy_reward` | 击杀得分 / 能量奖励 | 10 / 0 |

> ⚠️ 出现波次、权重、数量**不属于怪物数据**，写在 WaveData/EnemySpawnEntry 里。

### 2.3 创建敌人场景 `scenes/enemies/enemy_vibrio.tscn`（继承 enemy_base）

```text
[gd_scene load_steps=4 format=3]

[ext_resource type="PackedScene" path="res://base/enemy_base/enemy_base.tscn" id="1_base"]
[ext_resource type="Resource" path="res://data/enemies/enemy_vibrio.tres" id="2_data"]
[ext_resource type="Texture2D" path="res://Textures/enemies/vibrio/vibrio.png" id="3_tex"]

[node name="EnemyVibrio" instance=ExtResource("1_base")]
monster_data = ExtResource("2_data")

[node name="Sprite2D" parent="Visual"]
scale = Vector2(0.6, 0.6)
texture = ExtResource("3_tex")
```

要点（**都是踩过的坑**）：

- 根节点继承 `enemy_base.tscn`，**不要**自己建 CharacterBody2D/血条/组件
- `monster_data` 必须指向 2.2 的资源
- 覆写贴图用 `name="Sprite2D"` + `parent="Visual"`——`Visual` 是基类里的节点，`Sprite2D` 挂在它下面
- 贴图暂缺先用 `res://Textures/enemies/basic/basic.png` 占位，后续替换
- 编辑器方式：`场景 → 新建继承场景(Ctrl+Shift+N)` → 选 `enemy_base.tscn` → 保存 → 根节点拖入 `monster_data` → 改 `Visual/Sprite2D` 的贴图/缩放 → 调 `CollisionShape2D` 尺寸匹配体型

### 2.4 注册到波次（决定它何时出现）

打开要用的波次资源 `data/waves/level_01_wave_01.tres`（或新建 `WaveData`）：

```text
[sub_resource type="Resource" id="entry_vibrio"]
script = ExtResource("2_entry")            # enemy_spawn_entry.gd
enemy_scene = ExtResource("4_vibrio")      # res://scenes/enemies/enemy_vibrio.tscn
count = 5
interval = 1.0
spawn_point_id = &"north"
```

在 `WaveData` 的 `entries` 数组里加这个 entry；再把该 WaveData 加进 `LevelData.waves`。

> 刷怪器自动按 WaveData 生成，**不用改任何关卡/刷怪代码**。不加注册 → 怪物永远不会出现。

### 2.5 验证

```powershell
godot --headless --path . -s res://tests/enemies/test_enemy_base.gd
godot --headless --path . -s res://tests/integration/test_complete_game_loop.gd
```

手动验证：生成 → 移动 → 塔索敌 → 子弹/激光掉血 → 血条更新 → 死亡一次 → 撞水晶扣血一次 → 删掉 HealthBar 不崩。

### 2.6 特殊能力敌人（按需）

普通敌人到此结束。分裂/护盾/治疗等能力做成**独立组件**（`extends Node`），挂到场景根节点下，监听 `MonsterBase.died` / `reached_target` 信号，不要改 `monster_base.gd`。参考 `base/enemy_base/components/` 现有组件写法。

## 3. 制作普通塔：完整流程

以新增「弧菌光束塔」为例。共 **3 个新文件 + 2 处修改**。

塔有两条实现路线：

- **路线 A：纯数值差异**（攻击模式、数值不同，逻辑同现有塔）→ 只建 `.tres`，脚本继承现有塔类或 `TowerBase`
- **路线 B：攻击方式不同**（子弹/激光/范围/特殊弹道）→ 建脚本覆写 `_fire()`，建场景

### 3.1 定义塔定位

决定：模式组合（生产/攻击/充能，用 `can_produce` / `can_attack` / `can_conduction` 布尔）、攻击方式、数值。

### 3.2 创建数据资源 `data/towers/vibrio_beam_stats.tres`

```text
[gd_resource type="Resource" script_class="TowerData" format=3]

[ext_resource type="Script" path="res://base/tower_base/tower_data.gd" id="1_data"]

[resource]
script = ExtResource("1_data")
tower_id = &"vibrio_beam"
display_name = "弧菌光束塔"
build_cost = 30
attack_range = 300.0
attack_interval = 0.2
base_damage = 10.0
charge_range = 400.0
```

`TowerData` 常用字段（均有默认值，按需覆盖）：

| 分组 | 字段 | 说明 |
|---|---|---|
| Identity | `tower_id` `display_name` `icon` `build_cost` | 标识 / 显示名 / 图标 / 建造花费 |
| 基础 | `attack_range` `attack_interval` `base_damage` `charge_range` | 攻击半径 / 攻击间隔 / 单发伤害 / 传导半径 |
| 生产 | `production_interval` `production_by_charge` | 生产间隔 / 按层产量 [5,12,20,30] |
| 充能 | `supply_budget` | 供能方层数 → 供给层数 [1,2,3,3] |
| 攻击增幅 | `laser_count` `damage_mult` | 按层同时攻击数 [1,2,3,4] / 伤害倍率 [1.0,1.2,1.33,1.5] |
| 超频 | `overclock_damage` `overclock_range` `overclock_cooldown` `overclock_production` | 攻击超频贯穿伤害 / 扫射距离 / 冷却 / 生产超频产量 |

### 3.3 创建塔脚本 `scripts/towers/vibrio_beam.gd`

```gdscript
class_name VibrioBeamTower
extends TowerBase

func _fire(target: Node2D, mult: float) -> void:
    # 攻击塔必覆写：对 target 造成伤害（mult 是当前充能伤害倍率）
    if target == null or not target.has_method("take_damage"):
        return
    target.take_damage(roundi(config.base_damage * mult))
    _show_beam(target)   # 自己写激光视觉

func _show_beam(target: Node2D) -> void:
    var line := Line2D.new()
    line.points = PackedVector2Array([Vector2.ZERO, target.global_position - global_position])
    line.width = 3.0
    line.default_color = Color(1.0, 0.9, 0.2, 0.9)
    add_child(line)
    var tw := create_tween()
    tw.tween_property(line, "default_color:a", 0.0, 0.15)
    tw.tween_callback(line.queue_free)
```

常用覆写点（继承 `TowerBase` 后按需覆写，需要时记得调 `super`）：

| 钩子 | 作用 |
|---|---|
| `_fire(target: Node2D, mult: float)` | 开火效果（激光/子弹/范围），攻击塔必覆写 |
| `_link_gained(level: int) -> int` | 供能方层数 → 供给目标层数（默认 1） |
| `_on_linked(target: TowerBase, gained: int)` | 链接建立后触发特殊效果（如超频判定） |
| `_do_overclock()` | 超频大招效果 |
| `_production_amount() -> float` | 单次产量（默认按层读 config） |
| `_on_mode_entered(m: int)` / `_on_mode_exited(m: int)` | 模式切换钩子 |

**子弹塔参考**（`PlasmaCellTower`，见 `scripts/towers/tower_plasma_cell.gd`）：`_fire` 里实例化子弹场景、调用 `bullet.setup(target, damage, speed)`。

### 3.4 创建塔场景 `scenes/towers/vibrio_beam.tscn`

结构必须含基类引用的四个固定节点（`ClickArea` / `Visual` / `AttackTimer` / `ProductionTimer`）：

```text
[gd_scene load_steps=6 format=3]

[ext_resource type="Script" path="res://scripts/towers/vibrio_beam.gd" id="1_script"]
[ext_resource type="Resource" path="res://data/towers/vibrio_beam_stats.tres" id="2_data"]
[ext_resource type="Script" path="res://base/tower_base/tower_visual.gd" id="3_visual"]
[ext_resource type="Texture2D" path="res://Textures/towers/vibrio_beam/vibrio_beam.png" id="4_tex"]

[sub_resource type="RectangleShape2D" id="click_shape"]
size = Vector2(64, 64)

[node name="VibrioBeam" type="Node2D"]
script = ExtResource("1_script")
config = ExtResource("2_data")
can_produce = true
can_attack = true
can_conduction = true

[node name="ClickArea" type="Area2D" parent="."]
unique_name_in_owner = true

[node name="CollisionShape2D" type="CollisionShape2D" parent="ClickArea"]
shape = SubResource("click_shape")

[node name="Visual" type="Node2D" parent="."]
unique_name_in_owner = true
script = ExtResource("3_visual")

[node name="Sprite2D" type="Sprite2D" parent="Visual"]
texture = ExtResource("4_tex")

[node name="AttackTimer" type="Timer" parent="."]
unique_name_in_owner = true

[node name="ProductionTimer" type="Timer" parent="."]
unique_name_in_owner = true
```

要点：

- 根节点脚本 `extends TowerBase`，`config` 拖 3.2 的资源
- `can_*` 三个布尔决定模式循环里跳过哪些（只有攻击 → 只勾 `can_attack`）
- 子弹塔额外加 `ProjectileOrigin (Marker2D)`（`unique_name_in_owner = true`），脚本用 `%ProjectileOrigin`
- 有充能模式时，供能方链接/范围圈由 `TowerBase` 自动处理，无需额外代码

### 3.5 注册到塔目录 + 关卡允许列表

1. **`data/catalogs/tower_catalog.tres`**：加一个 `TowerCatalogEntry` 子资源，`tower_id`、`data`（3.2 的资源）、`scene`（3.4 的场景）都填上，并加进 `entries` 数组。
2. **关卡允许**：打开 `data/levels/level_01.tres`，在 `allowed_tower_ids` 数组加 `&"vibrio_beam"`——不加则建塔 UI 点了会提示 `tower_not_allowed`。

### 3.6 验证

```powershell
godot --headless --path . -s res://tests/levels/test_tower_placement.gd
godot --headless --path . -s res://tests/integration/test_complete_game_loop.gd
```

手动验证：选塔 → 点格子 → 扣能量 → 格子占用 → 敌人进范围自动攻击 → 死亡不重复结算。

## 5. 常见错误排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 敌人看不见但血条在动/水晶掉血 | 继承场景覆写写法错误（`name="Visual/Sprite2D"`） | 改成 `name="Sprite2D"` + `parent="Visual"` |
| 怪物不出现 | 没注册进 WaveData/EnemySpawnEntry | 第 2.4 步 |
| 塔点了没反应/提示 tower_not_allowed | 没加进 `TowerCatalog` 或关卡 `allowed_tower_ids` | 第 3.5 步 |
| 报 `MonsterBase requires MonsterData` / 塔没数值 | 场景根节点 `monster_data` / `config` 没拖 `.tres` | 检查器拖入资源 |
| 血条不更新/报错 `HealthBar` | 场景没继承 base（自己另建） | 继承 `enemy_base.tscn` / `tower_base.tscn` |
| 敌人撞水晶不掉血 | 敌人到达判定与水晶碰撞半径不匹配 | 保持 `CollisionShape2D` 半径 ≤ 32（水晶碰撞半径） |
| 编辑器报 `.tres` 类型错误 | 手写资源时 `script_class` 或脚本路径错 | 对照 2.2 / 3.2 模板 |
| 报 `Too few arguments for new()` | 把 `init` 写成了 `_init`（构造函数需传参） | 用普通方法 `func init(...)` |

## 6. 提交规范

- 分支：`feature/<内容>-enemy` 或 `feature/<内容>-tower`
- 提交信息：`feat: 新增弧菌敌人` / `feat: 新增弧菌光束塔`
- 一个 PR 只做一个内容；PR 描述写「改了什么、为什么、怎么测的」
- 禁止提交 `.godot/`、`.uid` 缓存、本地备份；`monster_base.gd` / `enemy_base.tscn` / `tower_base.gd` 等公共文件改动需提前沟通
