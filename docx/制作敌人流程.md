# 敌人制作流程（Enemy Creation Guide）

> 本文档说明如何在本项目（Godot 4.6，目录结构 `base/` `scenes/` `data/` `scripts/` `level/`）中新增敌人。
> 适用于：团队成员、外包协助者。普通敌人按本文档可独立完成；特殊能力敌人需先读第 5 节。

---

## 0. 系统架构（先读 3 分钟，避免踩坑）

敌人系统采用 **基类 + 组件 + 数据资源** 结构：

```
敌人场景（继承 enemy_base.tscn）
├── CharacterBody2D（根节点，挂 monster_base.gd 脚本）
│     ├── Sprite2D              ← 继承得到，子类改贴图/缩放
│     ├── CollisionShape2D      ← 继承得到，子类改形状/尺寸
│     ├── HealthBar             ← 继承得到，血条
│     └── HealthNumber          ← 继承得到，血量数字
└──（可选）特殊能力组件         ← 分裂/护盾/治疗等，按需挂
```

- `monster_base.gd`（`base/enemy_base/`）：唯一怪物基类，统一提供公共契约——
  - 加入 `enemy` 分组（塔索敌、水晶碰撞都靠它）
  - `setup_target(target)`（刷怪器调用，指定移动目标=水晶）
  - `take_damage(amount)` / `heal(amount)`（塔/子弹调用）
  - `damage` 属性（撞水晶伤害，关卡读取）
  - 内部组件：`HealthComponent`（血量/死亡）、`MovementComponent`（移动/减速预留）
  - 到达水晶附近（距离 < 20）停下，扣血和销毁由关卡水晶碰撞统一处理
- `enemy_base.tscn`（`scenes/enemies/`）：**统一基础场景**。新敌人必须**继承它**，不要新建 CharacterBody2D、不要复制血条节点。
- `monster_data.gd` + `data/enemies/*.tres`：怪物静态数值资源（血量/速度/伤害/类别）。

**红线**：普通敌人**禁止修改 `monster_base.gd`**。需要新能力时按第 5 节加独立组件。

## 1. 文件目录约定

| 内容 | 位置 | 命名 |
|---|---|---|
| 怪物贴图 | `Textures/enemies/<怪物名>/` | 如 `vibrio.png` |
| 怪物数据资源 | `data/enemies/` | `enemy_<怪物名>.tres` |
| 怪物场景 | `scenes/enemies/` | `enemy_<怪物名>.tscn` |
| 特殊能力组件 | `scripts/enemies/components/`（如不存在则新建） | `split_component.gd` 等 |
| 关卡注册 | `level/<N>_level/<N>_level.gd` 的 `ENEMY_TYPES` | 加一行 preload |

命名一律**英文小写蛇形**（文件名） + **帕斯卡**（场景根节点名 `EnemyVibrio`）。**不要用 `1_Enemy` 这种编号命名。**

## 2. 制作普通敌人：完整流程

以新增「弧菌 Vibrio」为例。共 2 个新文件 + 1 个文件修改。

### 步骤 2.1 定义敌人定位（动笔前）

回答三个问题：

- 普通 / 快速 / 肉盾 / 精英 / Boss？→ 决定 `monster_type` 和数值
- 基础数值：生命、移速、撞水晶伤害、击杀得分
- 有无特殊能力？→ 有则先看第 5 节，普通怪跳过

示例（弧菌）：普通怪，血量 120，移速 60，伤害 10，得分 10。

### 步骤 2.2 创建数据资源 `data/enemies/enemy_vibrio.tres`

**方式 A：手写文件**（内容如下，`uid` 留空让 Godot 首次打开时自动生成）：

```
[gd_resource type="Resource" script_class="MonsterData" format=3]

[ext_resource type="Script" path="res://base/enemy_base/monster_data.gd" id="1_data"]

[resource]
script = ExtResource("1_data")
monster_name = "弧菌"
max_health = 120
move_speed = 60.0
damage = 10
score_value = 10
monster_type = 0
```

**方式 B：编辑器创建**：文件系统面板右键 `data/enemies/` → **New Resource...** → 类型选 `MonsterData` → 保存为 `enemy_vibrio.tres` → 检查器填字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `monster_name` | 显示名 | 弧菌 |
| `max_health` | 最大生命 | 120 |
| `move_speed` | 移动速度 | 60.0 |
| `damage` | 撞水晶伤害 | 10 |
| `score_value` | 击杀得分（预留） | 10 |
| `monster_type` | 类别：0=普通 / 1=精英 / 2=Boss | 0 |
| `armor` | 抗性 0~1（实际承伤 ×(1-armor)） | 0.0 |
| `negative_status_resistance` | 负面效果抗性 0~1 | 0.0 |

> ⚠️ 波次、出现关卡、权重、数量**不属于怪物数据**，不要写进 `.tres`（以后由 WaveConfig 管理）。

### 步骤 2.3 创建敌人场景 `scenes/enemies/enemy_vibrio.tscn`

**方式 A：手写文件**（内容如下）：

```
[gd_scene load_steps=4 format=3]

[ext_resource type="PackedScene" path="res://scenes/enemies/enemy_base.tscn" id="1_base"]
[ext_resource type="Resource" path="res://data/enemies/enemy_vibrio.tres" id="2_data"]
[ext_resource type="Texture2D" path="res://Textures/enemies/1_enemy/1_enemy.png" id="3_tex"]

[node name="EnemyVibrio" instance=ExtResource("1_base")]
monster_data = ExtResource("2_data")

[node name="Sprite2D" parent="."]
scale = Vector2(0.6, 0.6)
texture = ExtResource("3_tex")
```

**方式 B：编辑器创建（推荐）**：

1. 菜单 **场景 → 新建继承场景（Ctrl+Shift+N）** → 选 `res://scenes/enemies/enemy_base.tscn`
2. 保存为 `enemy_vibrio.tscn`
3. 根节点 `EnemyVibrio`：把步骤 2.2 的 `enemy_vibrio.tres` 拖进 `monster_data`
4. 选 `Sprite2D`：换成自己的贴图，调 `scale` 匹配体型（参考 0.6）
5. 选 `CollisionShape2D`：调整 `CircleShape2D` 半径匹配贴图
6. `HealthBar` / `HealthNumber`：一般不用动；**不要删除这两个节点**

要点：

- 根节点必须是 `instance=ExtResource("1_base")`（继承 enemy_base），**不是**自己建 `CharacterBody2D`
- `monster_data` 必须指向步骤 2.2 的资源，否则运行时报 `MonsterBase: 场景里没有配置 monster_data 资源`
- 贴图暂缺时先用 `1_enemy.png` 占位，后续替换

### 步骤 2.4 注册进关卡（最容易漏的一步！）

打开要出现该怪物的关卡脚本 `level/<N>_level/<N>_level.gd`，在 `ENEMY_TYPES` 数组加一行：

```gdscript
const ENEMY_TYPES := [
	preload("res://scenes/enemies/enemy_streptococcus.tscn"),
	preload("res://scenes/enemies/enemy_vibrio.tscn"),   # ← 新增
]
```

- 刷怪器自动从数组 `pick_random()` 随机刷怪，**不用改刷怪器**
- 不加这一行 → 怪物永远不会出现
- 想让怪物出现在哪几关，就在对应关卡的 `ENEMY_TYPES` 里加

### 步骤 2.5 自测验证

在 Godot 里运行该关卡，逐项确认：

1. 敌人能生成，`setup_target` 后朝水晶移动
2. 塔能索敌到它（`enemy` 分组生效）
3. 子弹命中掉血，血条数字同步减少
4. 血尽只销毁一次，控制台无报错
5. 撞到水晶只扣一次血，敌人销毁（`monster_base.gd` 距离 <20 停下 → 水晶碰撞回调扣血+销毁）
6. 临时删掉它的 `HealthBar` 节点再跑一次——不崩溃（`get_node_or_null` 保护）

批量压力测试（可选）：把 `ENEMY_TYPES` 多加几种怪、同时刷几十只，确认无目标失效、无重复死亡、帧率正常。

## 3. 制作特殊能力敌人（分裂/护盾/治疗等）

原则：**能力做成独立组件挂到场景上，不塞进 `monster_base.gd`**。

### 3.1 先给 monster_base.gd 补公共信号（只做一次，团队确认后由负责人改）

在 `monster_base.gd` 顶部信号区加：

```gdscript
signal died
signal reached_target
```

在 `die()` 里加一行：`died.emit()`
在 `_physics_process` 到达水晶处（距离 < 20 的 return 前）加一行：`reached_target.emit()`

> ⚠️ 这是公共文件，按团队规范（`docx/CONTRIBUTING.md`）由负责人确认后修改。

### 3.2 示例：分裂组件 `scripts/enemies/components/split_component.gd`

```gdscript
class_name SplitComponent
extends Node

@export var split_scene: PackedScene   # 分裂出的子怪场景（检查器拖入）
@export var split_count: int = 2

var _owner: MonsterBase

func _ready() -> void:
	_owner = owner as MonsterBase
	if _owner == null:
		push_error("SplitComponent 必须挂在 MonsterBase 场景根节点下")
		return
	_owner.died.connect(_on_owner_died)

func _on_owner_died() -> void:
	for i in range(split_count):
		var child := split_scene.instantiate() as MonsterBase
		if child == null:
			continue
		_owner.get_parent().add_child(child)
		child.global_position = _owner.global_position + Vector2(randf_range(-10.0, 10.0), randf_range(-10.0, 10.0))
		child.setup_target(_owner.move_target)
```

### 3.3 挂载组件

1. 打开敌人场景（如 `enemy_vibrio.tscn`）
2. 根节点下新建子节点 `Node`，改名为 `Split`
3. 给 `Split` 挂 `split_component.gd`，检查器里把子怪场景拖进 `split_scene`，设 `split_count`

组件自包含（监听信号 + 自己实例化），`monster_base.gd` 一行不用动。

## 4. 常见错误排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 控制台报 `MonsterBase: 场景里没有配置 monster_data 资源` | 场景的 `monster_data` 没拖 `.tres` | 把数据资源拖进根节点 `monster_data` |
| 怪物不出现 | 没在 `ENEMY_TYPES` 注册 | 步骤 2.4 |
| 场景打开报找不到脚本/资源 | `.tres`/`.tscn` 路径写错或文件被移动 | 检查 ext_resource 的 `path` |
| 血条不显示但报错 `HealthBar` | 场景里没建 `HealthBar` 节点 | 继承 `enemy_base.tscn` 就会有，不要自己另建不带该节点的场景 |
| 撞水晶不掉血 | 距离判断与碰撞半径不匹配 | 保持 `CollisionShape2D` 半径 ≤ 32（水晶碰撞半径），且别在怪物侧自己 `queue_free` |
| 怪物贴图是别人的/错图 | 贴图路径写错 | 检查 tscn 里 `Sprite2D` 的 texture |
| 编辑器报 `.tres` 类型错误 | 手写资源时 `script_class` 或脚本路径错 | 对照 2.2 模板，确认指向 `monster_data.gd` |
| 敌人被打死后报"重复释放" | 死亡逻辑与外部同时 `queue_free` | 普通流程下不会发生；若加了能力组件，确认组件不额外销毁 owner |

## 5. 提交规范（团队协作）

按 `docx/CONTRIBUTING.md` 执行，要点：

- 开分支：`feature/<怪物名>-enemy`，如 `feature/vibrio-enemy`
- 提交信息：`feat: 新增弧菌敌人（120血/60速）`
- 一个 PR 只做一个怪物；PR 描述写清「改了什么、为什么、怎么测的」
- **不要提交** `.godot/`、`.uid` 临时产物、本地备份文件
- 公共文件（`monster_base.gd`、`enemy_base.tscn`）改动必须提前沟通

---

## 6. 一句话速查

```
建 .tres（数值） → 建 .tscn（继承 enemy_base + 拖 monster_data + 换贴图）
→ 关卡 ENEMY_TYPES 注册 → 运行验证 → 开分支提 PR
特殊能力：加独立组件挂场景，公共信号先让负责人补
```
